# AlarMe browser pause/restart evidence

The exact official AlarMe 1.6.3/store 124 frontend was rendered by Framey's production panel renderer and host at commit `3ec43ad6a5af1df55a8190015f7802cc18190511`, using an opaque sandboxed iframe in a private, networkless AMD64 QEMU VM. The managed backend was installed through the production apply script and ran under pinned published Decky 3.3.0. A local synthetic bridge forwarded the real timer RPC and events; this did not exercise the production HTTP parent or Steam CEF.

Both paused timer cards remained visible after a clean loader restart, with the same `0:04` and `4:59` displays and exact frozen native remaining durations. The short paused timer also remained present. The separate native lifecycle fixture explicitly verifies restart after its original deadline has elapsed; this browser fixture did not record a wall-clock timestamp at restart. The actual frontend Resume control produced one silent completion event for the short timer, and the actual Cancel control removed the remaining long timer. Final native readback had no active timers and no active sleep inhibitor. The final capture also shows the frontend's Timer Finished notification.

[Before restart](framey-alarme-browser-beforeRestart-2026-10-30.png), [after restart](framey-alarme-browser-afterRestart-2026-10-30.png), and [empty active list](framey-alarme-browser-empty-2026-10-30.png) were all visually inspected. All 88 transported product input hashes match the exact commit. The checksummed result packet, RPC/event readback, renderer seccomp/NoNewPrivs and browser ancestry, and cleanup passed independent audit. Both loader stops exited zero, in 1.009 and 0.980 seconds; the retained loader log records two complete shutdowns without the checked cancellation/shutdown-error markers. Browser, native event sockets, HTTP server, loaders, guest user manager and QEMU were stopped/reaped.

The auxiliary probe, runner and shared browser bridge were separately fingerprinted and frozen under the local evidence root recorded in [the report](framey-alarme-browser-restart-2026-10-30.json). They were outside the tested product commit. Two earlier harness failures are retained: an existing empty VM directory and an early DevTools title query. Neither is treated as a product regression. The independent auditor initially assumed the window size equalled the capture viewport; the actual Chromium content viewport is 1240 by 1013, and every PNG payload and dimension was checked after that correction. No product assertion or runtime failure was waived.

This is a synthetic browser/private-bridge result. It does not verify sound, sleep inhibition, production HTTP integration, Steam CEF, real Frame display pixels, wearer visibility or physical controller usability. Compatibility remains partial. Existing managed copies still need update/reinstall for the paused-restart guard. Exact-head CI and future refreshed-head checks remain required before merge.
