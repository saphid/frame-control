# Frame Control v0.4.62 release verification

Published **14 November 2026 at 04:28:46 UTC** as
[v0.4.62](https://github.com/saphid/frame-control/releases/tag/v0.4.62),
from commit `0b05d2a174da9ff84ed654de0b746e1fcdb9a178`.
The existing tag was neither moved nor deleted.

## Exact-commit hosted checks

The publication preflight checked every matching run and attempt, including
the required jobs, using the repository's release-gate functions. All passed:

- [Main CI and fake-Frame e2e](https://github.com/saphid/frame-control/actions/runs/43531611881): seven jobs.
- [Native AMD64 and ARM64 Decky runtime](https://github.com/saphid/frame-control/actions/runs/43531611792): two jobs.
- [Syncthing ownership/watchdog, peer runtime and isolated user service](https://github.com/saphid/frame-control/actions/runs/43531611787): two jobs.
- [Signed Syncthing package checks](https://github.com/saphid/frame-control/actions/runs/43531611788): AMD64, ARM64, browser HTTP and production-parent HTTP.
- [Tagged installer builds and checksums](https://github.com/saphid/frame-control/actions/runs/43531646796): draft, four platform builds and checksums.

The tagged workflow checked both Mac DMG/ZIP payloads and runner architectures,
installed the Windows package and compared its resources, exercised the installed
Windows Python with the PC libraries, and launched the Linux x86_64 AppImage
on an isolated Xvfb display. These are hosted checks; they do not establish
acceptance on a physical Mac, Windows PC or headset.

## Independent installer and update-channel audit

Before publication, `scripts/audit-release-assets.py` independently downloaded
all ten installers by asset ID, matched their sizes and SHA-256 digests to
GitHub metadata, verified the downloaded `SHA256SUMS`, and checked package
formats and available version/architecture metadata. The Linux x86_64 AppImage
answered HTTP 200 with `FrameControl/1` on an isolated Xvfb display; its server
stopped when the app exited. The publisher's dry run passed against this audit.

The publisher uploaded `update.json`, verified its digest and downloaded its
bytes for an exact readback before publishing. A fresh audit after publication
downloaded every installer again and verified the public update manifest's
version, page, release notes and ten installer records against the release.
The [post-publication audit report](v0462-release-assets-2026-11-14.json) retains
the package hashes and inspection results.

For a new independent audit, choose a new output file:

```sh
python3 scripts/audit-release-assets.py v0.4.62 \
  --report /tmp/frame-v0462-public-audit.json --launch-x86-appimage
```
