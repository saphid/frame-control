# Static x86 FEX feasibility, 29 October 2026

On main `ed8591438aff5107a91b99522a9173fa795994b9`, a read-only probe
acquired `/tmp/frame-test.lock` with a unique owner before reading the Frame.
SteamVR activity was 3 (standby), proximity 2.3125 and battery 99%. The Frame
has `FEX-Emu/usr/bin/FEX` but no installed `SteamLinuxRuntime_4` in either
checked Steam common path. `FEX-Emu/rootfs` was empty. The probe released only
its own lock.

A second uniquely locked run used the same standby and proximity preflight,
then ran `tests/smoke/tiny_programs.py`'s static x86-64 ELF (two-second sleep)
through the installed `FEX` executable. It exited 0 in 3.03 seconds with no
output. The run used a private `/tmp` home, config, cache, data and runtime
directory, set an owner marker on child processes, stopped zero owned residual
processes, removed its private directory, and released its lock. It did not
register a Steam title, change Steam or VR settings, wake the headset, or send
controller input.

This proves only a direct static x86-64 FEX execution path on this Frame OS
build. A Steam devkit title using a Frame Control launcher, dynamic x86-64
binaries, ordinary games, wearer-visible output and controller input remain
unverified. The v0.4.54 release stays held until the exact release commit has
a zero-skip locked smoke result and all other release gates pass.
