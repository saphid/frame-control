# Isolated browser probe background components

The signed-package browser probe needs its loopback page and opaque plugin panel. Native Chrome 150 also started unrelated default component-extension renderers despite the existing `--disable-background-networking` flag. Add `--disable-component-extensions-with-background-pages` to this private probe and its existing native startup regressions.

On an exact reconstruction of main `27d62870`, a native x86 trace recorded three component-extension script evaluations and two Extension Renderer processes. The otherwise unchanged flag variant recorded neither. These are single native samples, not an ARM performance measurement; nested trace durations must not be added as independent costs. The baseline application assertions passed, but its profiler cleanup adapter failed; the retained trace's actual owned process group was subsequently stopped and verified empty. The variant passed its application assertions and owned cleanup with Seccomp 2 / NoNewPrivs 1 renderer state.

All three existing browser methods then passed with the edited launch settings: streaming parent/child delivery (including a seven-second delay and two-MiB padding), pinned full frontend initialization, and native listener ordering including the never-ready control. Five owned browser launches retained renderer sandboxing and left no live owned processes. The first private batch omitted the pinned archive, so the full-frontend method did not execute; only that method ran after the archive was supplied. Separately, 37 focused nonbrowser methods passed. A restricted-sandbox socket error and three opt-in local browser skips are retained; only the socket-blocked method was rerun with socket access, and the three browser methods passed on the native route described above.

AST comparison proves the only executable changes are three added command-line arguments: one in the signed-package probe and two in its startup test launch sites. Production files, readiness logic, the 60-second readiness gate, eight-second RPC budget, browser sandbox and owned cleanup are unchanged. The parent, opaque child, frontend and pinned archive inputs remain bound in the JSON and compressed raw records.

The original main ARM browser readiness failure was not reproduced in these native experiments. These observations do not establish its cause, an ARM speedup, a general readiness repair, real Frame behavior, controller input or worn/VR operation. Fresh original hosted checks and signed artifacts remain required. The failed main run and all historical attempts remain failed and retained.
