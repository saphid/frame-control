# Deck Progress Tracker original unload failure

The exact official store 134 Deck Progress Tracker 1.3.6 ZIP has SHA-256 `784c59e7e2a344eb6803d00e341c7d5f10d42cea7b60cc4332f4c3687db14fb3`. It was downloaded from the official CDN and digest-checked; no fresh complete store-list claim is made.

An owned network/device-isolated published Decky 3.3.0 AMD64 replay at source `b8051523c48f8852924ae922264abe221c04ba66` answered 18 real API1 calls for private manual tags/settings. Read-only SQLite queries observed the selected rows and preservation boundaries. The original archive members remained unchanged, including its license. No Steam files or external lookup service were used.

**This is a lifecycle failure, not a qualified pass.** The initial runner returned zero because its checks accepted a zero-exit parent and reaped descendants. Independently inspected retained console shows two plugin `Sending SIGKILL!` warnings: Decky forcibly terminated each plugin after its five-second unload deadline. Parent exit zero does not prove graceful plugin unload. The fixture has been tightened to reject those warnings. The [failure audit](framey-deck-progress-original-unload-failure-2026-10-31.json) preserves the full original console and source hashes instead of relabeling this as a successful restart.

A follow-up snapshot fixture first failed on Python import scoping after shutdown; that fixture error is corrected separately. Temporary private instrumentation of the original plugin also reproduces forced kills. It observes cancellation of the dropped-games task on the same event loop and reaches database close without a completion message. The exact cause of the close wait is not yet proven. Instrumented runs modify private fixture bytes and cannot qualify official compatibility.

At this original diagnostic stage, no compatibility rating or production installer code changed. Real Steam statistics, automatic tagging, HLTB lookup, frontend/backend integration, a managed Frame installation, wearer-visible UI and controllers remain unverified. Upstream HLTB TLS behavior was not exercised or changed. No headset, active session, security setting or pre-existing data was touched.

A separate [bounded source-only EOF reproduction](framey-decky-eof-candidate-2026-10-31.json) uses the exact unmodified `UnixSocket` class from Decky 3.3.0 commit `67196adfa9b299f20dfb0cc932e88a169417b7d5`. With an already-EOF private reader, it creates 100 empty-message tasks before a scheduled heartbeat runs. Its observer then stops task creation, cancels and joins the 99 owned tasks; the upstream done callback emits 99 expected `CancelledError` exceptions, counted by a temporary loop exception handler. This is not an error-free shutdown and does not execute the published loader or prove the native failure cause. No production loader repair is made. Temporary private plugin instrumentation has been removed from the fixture; the stricter forced-kill refusal remains.

## Bounded native shutdown controls

The [independently audited native controls](framey-deck-progress-native-stop-controls-2026-10-31.json) execute the digest-pinned published Decky 3.3.0 AMD64 binary in owned network/device-isolated containers:

- The original parent-only shutdown reproduces two forced plugin kills, after 5.273 and 5.223 seconds. All 18 private settings/manual-tag RPCs answer and independently decoded SQLite snapshots match the selected-delete boundaries. This remains a failed lifecycle result.
- A child-first signal control lets the unmodified plugin cancel its background task, close SQLite and log that it unloaded. The parent then fails its eight-second stop deadline; cleanup reaps the owned container. This is also a failed lifecycle result.
- A separate private child EOF guard prepends a diagnostic hook to the installed `main.py`. It calls the original `UnixSocket._read_single_line`, setting `self.active = False` only when the returned value is empty. The original backend remains its exact suffix and every other archive member is unchanged. With the same parent-only stop calls, both cycles close SQLite and finish in 0.214 seconds without forced kills. All 18 RPCs and decoded SQLite snapshots also match. The full consoles and modified-fixture hashes are retained.

This bounded intervention supports child IPC EOF starvation as a cause of the original unload failure. It changes private child transport behavior and is **not** an unmodified-plugin pass, production loader repair, compatibility upgrade or release gate. The strict real fixture still rejects forced kills. No diagnostic hook is added to the production installer or committed runtime fixture.

The control artifact's `originalStopProcedure` field compares a mode label to `parent`; it is therefore false for `eof-guard` even though that mode uses the original parent-only stop code. The audit records this field limitation explicitly. Its `productionLifecycleModified=false` means that production repository/installer code was not changed; the private process was deliberately patched.

Upstream v3.3.1 is available at commit `ffd103b9c1a4ce5bf305e7c0998eda6e05457dad`. Its `localsocket.py` is byte-identical to the pinned v3.3.0 source. No v3.3.1 binary has been executed here, and upgrading is not presented as a demonstrated fix. Those controls alone do not qualify the original plugin. The separately implemented managed repair below has its own native validation.


## Separately prepared managed repair

The [new native evidence](framey-deck-progress-ipc-eof-native-2026-10-31.json) at source `4c28a882ac96794d64d5459665362c7b94b5056c` qualifies a **managed adaptation**, not the unchanged upstream plugin. Only the exact store 134 digest above gets a small helper in `py_modules` and a header in `main.py`; the original backend remains its exact suffix and all other original archive members, including the BSD license, remain byte-identical. A changed ZIP gets no adaptation. Neither the published Decky binary nor other plugin processes are modified.

The helper delegates framing, message dispatch, replies and exceptions to Decky's existing transport. It turns only an empty read at actual EOF into a private exception caught at that connection's server loop. This prevents empty-message starvation while leaving the socket active for a later connection. Unit checks cover EOF/heartbeat progress, complete and partial frames, reconnection, inactive sockets and propagation of original dispatch errors. Removing only the EOF exit reproduces two bounded regression failures.

On frozen source, published Decky 3.3.0 AMD64 passes 18 repaired API1 settings/manual-tag calls and two parent-only zero-exit unloads without forced kills. The same runner then restores the original plugin and reproduces its 18 successful RPCs followed by two forced plugin kills; this is an explicit negative, never a qualified lifecycle pass. Raw consoles, eight source hashes, every unchanged archive-member hash and four independently decoded SQLite snapshots were audited. Container and image cleanup were independently confirmed. The first replacement-handler candidate also passed and is retained separately as historical evidence; the final helper wraps the original transport rather than duplicating it.

An earlier candidate failed import because its helper was placed at the plugin root; Decky adds only `py_modules` to the import path. That failed run also overlapped a fixture edit and cannot qualify the final source. Its [failure record](framey-deck-progress-ipc-import-failure-2026-10-31.json) is retained. The qualifying replay ran after the corrected/refined inputs were committed and frozen.

158 focused tests passed before the wrapper refinement; eight focused EOF/archive/runtime-coverage tests passed after it. The compatibility rating stays **partial**. Fresh exact-head CI, native ARM64, full e2e and every triggered signed-package check remain mandatory before merge. Browser/backend integration, actual Steam data, automatic tagging, HLTB lookup, badges, a real Frame install, worn visuals and physical controllers remain unverified. This preparation does not authorize a release.
