- **Works** requires verified useful plugin behavior with its real backend. Read the reason for the verified scope and remaining limits; it does not imply worn-VR verification.
- **Partial** means only a subset or a local fixture scope was verified, often just frontend/settings initialization. The remaining backend/device functionality is unverified; read the reason for the exact scope.
- **Broken** means a concrete archive, frontend or Steam dependency blocks the audited version. An artificial backend/network denial alone is not evidence that the real backend is broken.
- **N/A** means the plugin targets hardware or a display/UI surface that Framey does not provide. The store disables installation for these versions.

Only the exact managed DeckyFileServer, Decky Localsend, Emuchievements and Wine Cellar adaptations below can replace their published x86 helpers; other x86 archives remain blocked. The native compatibility constraints below remain specific to each plugin.

A [DeckyFileServer ARM64 follow-up](evidence/framey-fileserver-arm64-2026-10-27.md) ships an offline, digest-checked GPL helper build, corresponding vendored source and a build recipe. Only its exact managed archive can replace the x86 helper and remove its unnecessary root flag. Actual Decky 3.3.0 discovery/RPC and real Frame HTTPS private-fixture listing/download pass; uploads stay disabled. Hostname-DNS failures and empty optional arguments are repaired. Decky 3.3.0 still exposes `decky.HOME`; that call is unchanged. The plugin remains partial. A [directory-entry follow-up](evidence/framey-fileserver-path-entry-2026-10-29.md) provides an explicit path field in that managed panel while retaining saved history; it does not grant a generic file picker. Existing managed copies need update or reinstall. Live directory entry, uploads, generated thumbnails and worn VR remain unverified.

[Emuchievements managed helper evidence](evidence/framey-emuchievements-managed-2026-10-29.md) records the pinned upstream source, bounded archive extraction, no-shell Python invocation and byte-for-byte offline rebuilds for amd64 and ARM64. ## Evidence and maintenance

The canonical JSON contains full archive hashes, native paths, source URLs, frontend observations and fake-Frame outcomes. Store compatibility is advisory except known installation/hardware blockers; removal always remains available. A panel retains its compatibility reason after the initializer reports ready. Upstream fixes require a new digest-scoped audit. Do not mark a plugin works based on archive installation, fake backend replies or initializer completion.
