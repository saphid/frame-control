# Frame Control 0.4.63

- Framey notification actions now run once, even when an action synchronously
  triggers another click. Dismissed, expired and completed notifications retire
  their callbacks; an action that throws still dismisses its notification.
  [#696](https://github.com/saphid/frame-control/pull/696)
- Framey refuses plugin-ownership receipts larger than 16 KiB before parsing
  them. Invalid receipts continue to report an unknown installed state, keeping
  install/remove decisions conservative.
  [#695](https://github.com/saphid/frame-control/pull/695)

- Notebook regression checks now cover per-app pages, selections and strokes
  across a real Decky restart, including deletion that preserves other notes.
  [#497](https://github.com/saphid/frame-control/pull/497)

## Verification limits

Local browser, native Decky and hosted automated tests cover these changes.
Release qualification must separately verify this exact version's main CI,
installer builds, downloaded artifacts and locked real Frame smoke before
publication. Those results are not implied by this prepared note.

Framey's UI visibility in a worn headset, actual controller input, scrolling and
the VR keyboard remain unverified. No Windows machine is available for a physical
installer launch. Native Linux containers and local Chromium do not prove VR
behavior. The unresolved ARM64 Syncthing readiness/shutdown investigation remains
open; managed Syncthing support stays disabled.
